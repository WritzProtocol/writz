# writz-spv-client

Prove a Bitcoin transaction from your Soroban contract with the Writz `bitcoin-spv` light client.

`bitcoin-spv` stores Bitcoin block headers on Stellar, checks their proof-of-work and difficulty, and follows the most-work chain. `verify_transaction` proves that a transaction is in one of its blocks with at least N confirmations. This crate gives your contract the typed client, the result and error types, and an on-chain output parser, so you add one line to `Cargo.toml` instead of copying types or depending on a git commit.

`no_std`, `soroban-sdk` 26.

```toml
[dependencies]
soroban-sdk = "26"
writz-spv-client = "0.1"
```

```rust
use writz_spv_client::{find_output_value, BitcoinSpvClient};

// `spv` is the bitcoin-spv contract ID, stored at construction.
let proof = match BitcoinSpvClient::new(&env, &spv)
    .try_verify_transaction(&block_hash, &merkle_proof, &tx_index, &raw_tx, &6)
{
    Ok(Ok(result)) => result,          // SpvVerificationResult { txid, block_hash, block_height, confirmations }
    _ => return Err(Error::ProofRejected),
};

// Inclusion is proven; what the transaction paid is your check.
let sats = find_output_value(&raw_tx, &expected_script_pubkey).ok_or(Error::NotPaid)?;

// verify_transaction is a pure check: store the txids you accept.
```

## What is in it

| Item | What it is |
|---|---|
| `BitcoinSpvClient` | Generated by `#[contractclient]` from `BitcoinSpvInterface`: `verify_transaction`, `get_best_tip`, `get_header`, `get_canonical_hash`, `get_checkpoint`, `is_deposit_consumed`, each with a `try_` variant |
| `SpvVerificationResult`, `BestTip`, `HeaderEntry`, `Checkpoint` | The contract's types, decoded by field name |
| `SPVError` | The contract's error codes (stable, never reassigned) |
| `find_output_value(raw_tx, script_pubkey)` | Satoshi value of the first output paying exactly that scriptPubKey, for any script type; `None` if there is none or the transaction is malformed |
| `txid(env, raw_tx)` | SHA256d of `raw_tx`, internal byte order, the same value `verify_transaction` returns |

The tests check every type, error code and the parser against the `bitcoin-spv` source in the same repository.

## Arguments and byte order

Get the five arguments of `verify_transaction` from the Writz relayer, `GET https://api.testnet.writz.xyz/spv-proof/:txid`, field `sorobanArgs`. They are already in internal byte order (the reverse of what explorers show) and `raw_tx` has no witness data. The returned `txid` and `block_hash` are in internal byte order too.
