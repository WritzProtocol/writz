# Contributing to Writz

Thanks for helping. The full guide, with the module map, test commands and review expectations, is the [Contribution guide](https://docs.writz.xyz/developers/contribution-guide).

In short:

1. Fork the repo and branch from `main`.
2. Run the test suites of the modules you touch (commands in the [README](README.md#run-the-test-suites)); CI must pass.
3. Add tests for new features and a regression test for every bug fix.
4. Open a PR that says what changed and why. Commits follow [Conventional Commits](https://www.conventionalcommits.org/).

Security issues are never reported in public issues: open a private [GitHub Security Advisory](https://github.com/WritzProtocol/writz/security/advisories/new) and see [`SECURITY.md`](SECURITY.md).
